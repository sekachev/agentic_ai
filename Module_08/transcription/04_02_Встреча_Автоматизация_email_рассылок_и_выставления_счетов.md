Заметки о встрече
Адаптация и A/B-тестирование шаблонов email-рассылок
Обсуждалась возможность адаптации текстов email-рассылок на основе их
эффективности.
Предлагается не изменять шаблоны ежедневно, чтобы не испортить
удачный вариант из-за малой выборки.
Рекомендуется анализировать эффективность после рассылки по
значительной части базы (например, после 10-20 дней работы).
Если один из двух шаблонов показывает большую конверсию (например,
7% кликов против 5%), следует сосредоточиться на его улучшении.
Автоматизация отправки email с помощью агента
Рассмотрены два способа предоставления агенту доступа к Gmail для
автоматизации отправки писем.
Первый способ (сложный): Авторизация через командную строку (CLI)
с помощью Google Workspace CLI (ранее GWS). Этот метод требует
сложной настройки в Google Cloud.
Второй способ (простой): Использование “пароля приложения” (App
Password) из настроек аккаунта Gmail.
Пароль приложения представляет собой 16-значный код, который
предоставляется агенту вместе с логином для доступа к почтовому ящику.
Если отправлять до 100 сообщений в день, проблем с Gmail быть не
должно, так как Google проверяет отправителей для предотвращения


мошенничества.
Рекомендации по безопасности при автоматизации
Риск: Предоставление полного доступа к основному почтовому ящику
является небезопасным.
Рекомендация: Создать отдельный email-аккаунт специально для агента-
ассистента, чтобы избежать риска случайного удаления важных данных.
Пароли приложений и другие учетные данные не следует хранить в
общедоступных репозиториях, таких как GitHub.
Демонстрация автоматической отправки email

с темой “Привет” и картинкой гор.
Получатель подтвердил, что письмо и вложение были получены.
Интересно, что AI выбрал изображение гор, что оказалось связано с
общим воспоминанием участников о поездке в Непал.
Автоматизация создания и отправки счетов
Обсуждалась возможность автоматического создания счетов на основе
данных из базы и отправки их по email.
Агент получил задачу создать счет на 1000 евро для компании Дениса за
“создание красивой картинки”.
Агент смог найти в интернете данные компании Дениса по его email-
адресу, который связан с публичным реестром.
Был сгенерирован HTML-шаблон счета с данными продавца и покупателя.
При конвертации в PDF возникли проблемы с форматированием
(документ растянулся на 3 страницы).
ИИ-агент может использовать шаблон и данные из базы (например,
список из 200 клиентов) для генерации и отправки до 100 счетов в
формате PDF в день. Этот подход может заменить такие сервисы, как
Salesforce, так как логика задается языковыми командами.
Логика работы и управление ИИ-агентом
Агенту можно дать инструкции по обработке и перевыставлению счетов от
провайдеров (например, ежедневно проверять почту, собирать и
отправлять счета клиентам).
Предлагается добавить колонку “Статус” (например, “отправлено”,
“отклонено”) для отслеживания состояния отправлений.


Сложность вычислений для языковой модели растет квадратично от
количества слов в контексте, что замедляет работу в длинных сессиях.
Модели имеют ограниченное “контекстное окно”.
Рекомендуется использовать принцип “одна задача — одна сессия”. Для
сохранения контекста между сессиями предлагается использовать файл
Agents.md с описанием агента и папку Memory для долгосрочных знаний.
Предлагается использовать структуру, где одна папка соответствует
одному проекту, содержащему все необходимые файлы ( Agents.md,
Memory, база данных). Это позволяет изолировать контексты.
Интеграция с Telegram
Для работы бота в Telegram необходимо получить токен у BotFather.
Бот может отправлять сообщения пользователю только после того, как
пользователь сам инициировал общение (с ограничением по времени для
ответа).
Для отправки сообщения конкретному пользователю необходимо знать
его ID в Telegram.
Запуск и развертывание AI-агентов
Код для AI-агента должен быть постоянно запущен, для чего можно
использовать сервер (VPS).
Обсуждалась возможность использования локальной языковой модели
(LLM) через Ollama на собственном оборудовании, что может потребовать
настройки туннеля для связи с внешним миром.
Отправка SMS-сообщений
Для отправки SMS можно использовать сервисы типа bsg.world
(стоимость ~2,5 цента за SMS) или Android-телефон с приложением-
шлюзом.
При отправке через Android-телефон в качестве отправителя будет
отображаться номер SIM-карты.
Для сбора обратной связи через SMS предложено отправлять ссылку на
веб-форму, что экономичнее.
Интеграция с Instagram и телефония
Для интеграции с Instagram Business API нужно создать приложение через
Facebook API и получить токен. Возможность отвечать на сообщения
ограничена 24-часовым окном.


Обсуждалась возможность получения специального телефонного номера
через службу поддержки оператора связи.
Участники планируют протестировать новую версию телефонии (“Джинни
3.1”) для оценки сниженной задержки.

Предложения от ИИ
ИИ определил следующие проблемы, которые не были решены на
встрече или по которым отсутствуют четкие дальнейшие действия;
пожалуйста, обратите на них внимание:
1. Генерация PDF-счета привела к некорректному форматированию.
Необходимо разработать и протестировать надежный шаблон для
конвертации HTML в PDF.
2. Обсуждался риск предоставления доступа к почте, но не были
установлены конкретные протоколы безопасности, кроме
рекомендации создать отдельный email. Следует определить, как и
где безопасно хранить учетные данные.
3. Не было принято окончательного решения о том, как именно будет
реализована иерархическая структура управления агентами
(системный промт, agents.md, указания на уровне проекта).
4. Остался открытым вопрос о том, как агент должен поступать, если ему
для работы в одном проекте требуются данные, хранящиеся в другом.
5. Вопрос безопасности при предоставлении доступа к OpenClaw
третьим лицам остался открытым.
6. Не было принято окончательного решения о том, как лучше всего
организовать запуск AI-бота: локально или на удаленном VPS.


7. Обсуждение интеграции с социальными сетями было отложено без
определения конкретных сроков.
8. Не были определены конкретные сроки и ответственные для
тестирования новой модели телефонии.

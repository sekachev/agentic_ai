## Базовые роли в мультиагентной системе

```text
USER
  |
  v
ORCHESTRATOR   -> (PLANNER)  -> EXECUTOR
                      |
                      v
                   REVIEWER
```

---

## ORCHESTRATOR

+ <span style="color:orange">Задача</span>: понять, куда направить запрос
+ <span style="color:orange">Нужен</span>: когда есть разные задачи, каналы, сценарии
+ <span style="color:orange">Ошибка новичка</span>: орекстратор начинает сам решать задачу

---

## Planner

+ <span style="color:orange">Задача</span>: разбить сложную цель на этапы
+ <span style="color:orange">Нужен</span>: когда задача длинная и зависимая по шагам
+ <span style="color:orange">Ошибка новичка</span>: planner сам пишет финальный ответ вместо плана

---

## REVIEWER

+ <span style="color:orange">Задача</span>: проверять факты, риски и качество результата
+ <span style="color:orange">Нужен</span>: когда ошибка дорого стоит или нужен явный контроль качества
+ <span style="color:orange">Ошибка новичка</span>: reviewer превращается в еще одного исполнителя вместо независимой проверки

---

## EXECUTOR

+ <span style="color:orange">Задача</span>: выполнять поставленную задачу и писать отчет
+ <span style="color:orange">Нужен</span>: когда агент должен реально что-то менять во внешнем мире
+ <span style="color:orange">Ошибка новичка</span>: executor получает слишком много прав и слишком широкий доступ

## Блок 2: MCP
### Как агент подключается к внешним системам?

---

## MCP - Model Context Protocol

+ <span style="color:orange">Проблема</span>: у каждого сервиса свой API, auth и формат вызовов
+ <span style="color:orange">MCP</span>: единый протокол, через который агент получает доступ к инструментам и ресурсам (во внешнем мире)
+ <span style="color:orange">Эффект</span>: не нужно под каждый клиент заново придумывать способ подключения
+ <span style="color:orange">Аналогия</span>: MCP - это "USB-C для инструментов"

---

## MCP и Skills - не одно и то же

```text
MCP   -> как агент подключается к внешнему миру
Tool  -> какое конкретное действие он может выполнить
Skill -> как агент должен работать
```

+ Один и тот же <span style="color:orange">MCP server</span> можно использовать в разных агентах
+ В мультиагентной системе доступ через MCP лучше давать не всем, а только нужной роли

---
## MCPS.ee

## Блок 3: Skills
### Как задавать рабочую специализацию агенту?

---

## Skills
### Почему они так важны?

---

## Что такое Skill

+ <span style="color:orange">Не просто промпт</span>: это рабочая методика
+ <span style="color:orange">Не просто tool</span>: это не действие, а инструкция как действовать
+ <span style="color:orange">Не просто persona</span>: это прикладная специализация под задачу
+ <span style="color:orange">Физически</span>: папка с `SKILL.md` и, при необходимости, скриптами/ресурсами

---

## System Prompt vs Skill vs Tool

```text
System Prompt -> кто я
Skill         -> как я работаю
Tool          -> что я могу сделать
```

---

## Зачем Skill в реальной системе

+ <span style="color:orange">Сужает поведение</span>: меньше хаоса
+ <span style="color:orange">Повышает качество</span>: явный процесс работы
+ <span style="color:orange">Переиспользование</span>: одну методику можно переносить
+ <span style="color:orange">Масштабирование</span>: проще разделять роли между агентами

---

## Признаки хорошего Skill

+ Четкая цель
+ Узкая область
+ Понятные шаги
+ Явные критерии качества
+ Нет дублирования со всем остальным системным промптом

---

## Минимальная структура Skill

```text
my-skill/
  SKILL.md
  notes.md        (optional)
  scripts/...     (optional)
```

## Блок 4: OpenClaw
### Крабс!

---

## Почему вообще все говорят про OpenClaw

+ Это не просто еще один AI-чат
+ Проект показал образ <span style="color:orange">автономн ассистента</span>, который живет рядом с пользователем
+ Именно поэтому вокруг него быстро появился хайп, комьюнити и куча разборов

---

## Что делает OpenClaw уникальным

+ <span style="color:orange">Persistent memory</span>: агент помнит пользователя и рабочий контекст между сессиями
+ <span style="color:orange">Работает 24/7</span>: это не разовый чат-диалог, а постоянно доступный ассистент, который работает "в фоне"
+ <span style="color:orange">Живет там где ты</span>: Telegram, WhatsApp, Discord, iMessage и другие привычные интерфейсы
+ <span style="color:orange">Model-agnostic</span>: можно подключать разные LLM, а не жить на одном провайдере
+ <span style="color:orange">Skills + workspace</span>: поведение задается не только промптом, но и рабочей средой
+ <span style="color:orange">Multi-agent routing</span>: можно разносить роли, память и сценарии по разным агентам

---

## Как люди используют OpenClaw

+ Как <span style="color:orange">личного ассистента</span>: календарь, напоминания, заметки, ресерч
+ Как <span style="color:orange">операционный слой</span> для команды: Slack, Discord, GitHub, внутренняя база знаний
+ Как <span style="color:orange">автоматизатор</span>: собирать сводки, запускать рутины, дергать внешние сервисы
+ Как <span style="color:orange">песочницу для экспериментов</span>: skills, routing, memory, approvals на живой системе
+ В отзывах людям особенно нравится, что это не "еще один чат", а агент, который можно встроить в реальную работу

---

## Почему он так взлетел

+ Попал в сильный запрос: рынку надоели чат-боты, всем захотелось <span style="color:orange">AI, который реально действует</span>
+ Идея легко объясняется и вирусится: ассистент <span style="color:orange">помнит, работает в мессенджерах и делает задачи</span>
+ Open source сильно ускорил рост: комьюнити быстро понесло skills, интеграции и свои сценарии
+ Проект обсуждали не только из-за пользы, но и из-за <span style="color:orange">рисков</span>: безопасность, prompt injection, доступы, фейковые действия
+ То есть рост OpenClaw - это смесь <span style="color:orange">реальной полезности, хорошего продукта и громких споров</span>


---

## Где живет агент

+ По умолчанию workspace: <span style="color:orange">`~/.openclaw/workspace`</span>
+ Конфиги, креды и сессии живут отдельно в <span style="color:orange">`~/.openclaw/`</span>
+ Workspace - это рабочая директория агента, его "дом" и память

---

## Bootstrap файлы OpenClaw

+ <span style="color:orange">AGENTS.md</span>: рабочие инструкции и память
+ <span style="color:orange">SOUL.md</span>: persona, границы, стиль
+ <span style="color:orange">TOOLS.md</span>: заметки и соглашения по инструментам
+ <span style="color:orange">IDENTITY.md</span>: имя и базовая идентичность
+ <span style="color:orange">USER.md</span>: кто пользователь и как с ним работать
+ <span style="color:orange">HEARTBEAT.md</span>: короткий operational checklist
+ <span style="color:orange">BOOTSTRAP.md</span>: одноразовый первый запуск
+ <span style="color:orange">memory/YYYY-MM-DD.md</span>: ежедневная память и журнал

---

## Где живут Skills

+ Bundled skills: идут вместе с OpenClaw
+ Local skills: <span style="color:orange">`~/.openclaw/skills`</span>
+ Workspace skills: <span style="color:orange">`<workspace>/skills`</span>


---

## Sessions

+ <span style="color:orange">Session</span>: отдельный рабочий диалог
+ <span style="color:orange">Background processes</span>: spawned agents


---

## Где смотреть следы работы

+ Session logs: <span style="color:orange">`~/.openclaw/agents/<agentId>/sessions/*.jsonl`</span>
+ Gateway log file: <span style="color:orange">`/tmp/openclaw/openclaw-YYYY-MM-DD.log`</span>
+ Live tail: <span style="color:orange">`openclaw logs --follow`</span>

---

## Sandboxing и approvals

+ <span style="color:orange">Sandbox</span>: ограничивает видимость и запись
+ <span style="color:orange">Approvals</span>: останавливают рискованные команды
+ <span style="color:orange">Безопасность</span>: автономия без границ - плохая идея

---

## Кейс Крабса

+ <span style="color:orange">Крабс</span>: пример постоянного ассистента, который живет в своей рабочей среде
+ <span style="color:orange">На нем видно</span>: как вместе работают память, approvals, skills и внешние инструменты
+ <span style="color:orange">Задача кейса</span>: показать не теорию в вакууме, а реальную агентную систему под запуск

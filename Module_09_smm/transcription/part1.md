## 1. Проблема сбора данных (Краулинг и Парсинг)
Лекция началась с разбора ошибок при попытке собрать информацию с веб-сайтов для обучения AI-моделей.

*   **Основная ошибка:** Попытка скормить языковой модели (LLM) «сырой» HTML-код страницы.
    *   **Почему это плохо:** HTML современных сайтов перегружен служебными тегами, скриптами и стилями. Он занимает слишком много места (токенов). Контекстное окно модели быстро забивается, и она начинает «галлюцинировать» или просто перестает работать на 3-4 странице.
*   **Защита сайтов:** Крупные площадки (например, сайты недвижимости) используют жесткие методы борьбы с парсерами:
    *   Капчи (CAPTCHA).
    *   Обязательное принятие Cookies (без клика контент не отображается).
    *   Сложная структура тегов.
*   **Решение — Crawl4AI:** 
    *   Это специализированный инструмент («швейцарский нож»), который умеет управлять браузером как человек (скроллить, кликать).
    *   Он автоматически конвертирует содержимое сайта в формат **Markdown**, что в разы сокращает объем данных и делает их понятными для AI.
    *   Позволяет гибко настраивать «глубину» обхода сайта (по каким веткам ссылок идти, а по каким нет).

## 3. Бизнес-кейс: EstateGuru и P2P-инвестирование
Пример крупного финтех-проекта для понимания масштабирования и операционных болей.

*   **Что такое EstateGuru:** Платформа для P2P (peer-to-peer) инвестиций в недвижимость. Соединяет заемщиков (девелоперов) и частных инвесторов напрямую, минуя банки.
*   **Масштаб:** За 12 лет выдано около **970 млн евро** займов. Работает всего около 30 человек.
*   **Проблема «Нормального распределения» (Кривая Гаусса):** 
    *   Большинство инвесторов — мелкие (вкладывают по 30–250 евро).
    *   Крупных инвесторов (100к+ евро) — единицы.
    *   **Боль:** Мелкий инвестор требует столько же (или больше) внимания поддержки, сколько и крупный. Отвечать на 30,000 имейлов вручную — это затраты около **350,000 евро в год** только на зарплаты саппорта.
    *   **Решение:** Внедрение AI-ассистентов (например, «Мария») для автоматизации ответов и работы с базой знаний.

## 4. Архитектура данных: Базы данных vs Текстовые файлы

Один из ключевых споров лекции — где хранить информацию?

### Вариант А: Текстовые файлы (Markdown / Obsidian)
*   **Преимущества:** Идеально для AI. Модели работают с текстом через **векторные представления (эмбеддинги)**.
*   **Векторный поиск:** Модель ищет не по точному совпадению слова (как в Excel), а по смыслу. Например, поиск по вектору слова «Кино» найдет и «Терминатор», и «Железный человек», так как они семантически близки.
*   **Удобство для человека:** Файлы легко читать и редактировать в любом текстовом редакторе (VS Code, Obsidian).

### Вариант Б: Реляционные базы данных (SQL / Excel)
*   **Преимущества:** Идеально для математики и структурированных данных (финансы, даты, списки студентов).
*   **Пример:** Посчитать сумму аренды за год по конкретной квартире в текстовых файлах — мучение. В SQL — это один простой запрос.

### Итоговое решение: Гибридная архитектура
*   **SQL (База данных):** Для жестких структур (курсы, преподаватели, даты, время, списки учеников, счета).
*   **Markdown (Текстовые папки):** Для творческого контента (SMM-посты, стратегии, описания курсов, инструкции для агентов).

## 5. Организация SMM через AI-агентов
Подробная схема того, как должна выглядеть структура папок для автоматизации SMM:

*   **Иерархия папок:**
    *   `SMM/`
        *   `Strategy/` — общая стратегия бренда.
        *   `Content/`
            *   `2026/` (Год)
                *   `Week_01/` (Неделя)
                    *   `2026-01-17/` (Дата)
                        *   `Instagram/` (Канал) — здесь лежит `post.md` и `image.jpg`.
                        *   `Facebook/`
*   **Frontmatter:** В начале каждого Markdown файла (`.md`) рекомендуется добавлять блок метаданных (заголовок, дата, теги, источник) в формате YAML. Это позволяет AI быстро индексировать контент.
*   **README.md в каждой папке:** Обязательный файл-путеводитель для AI-агента, объясняющий, что лежит в этой директории.

## 6. Механизмы автоматизации (Heartbeat и Cron)
Как заставить систему работать саму по себе?

1.  **Heartbeat («Сердцебиение»):** Служба, которая просыпается с определенной периодичностью (например, каждые 30 минут) и проверяет, нет ли новых задач или сообщений.
2.  **Cron (Планировщик):** Позволяет задавать сложные условия запуска. Например: «Каждый третий четверг месяца в 12:00» или «После дождичка в четверг».
3.  **Claude (AI-агент) как исполнитель:** 
    *   Преподаватель использует Claude (через API) как «младшего специалиста».
    *   Ей дают инструкцию, базу знаний и доступ к папке SMM.
    *   Она сама проверяет почту, генерирует посты по графику и даже может выставлять счета (через сторонние библиотеки, например, генерация PDF).

## 7. Технический стек и команды
*   **Git:** Основной инструмент синхронизации.
    *   `git add .` — добавить изменения.
    *   `git commit -m "сообщение"` — зафиксировать.
    *   `git push` — отправить в облако.
    *   `git pull` — забрать актуальные данные (используется AI-агентом для обновления знаний).
*   **Markdown (.md):** Основной формат хранения текстов.
*   **CSV/SQL:** Формат для табличных данных.

## 🚀 Введение: От хаоса к структуре

Основная цель занятия — понять, как перейти от хранения данных «на салфетке» или в разрозненных Excel-файлах к структурированной базе данных (БД), которой можно управлять программно. Мы учимся не просто нажимать кнопки, а понимать архитектуру.

### Инструментарий
Для работы мы используем среду разработки (IDE) и расширения:
1.  **VS Code (или форки типа Cursor/Antigravity/KiloCode):** Основная среда для написания кода.

3.  **Языковая модель (LLM):** Используется как ассистент для генерации SQL-запросов, скриптов миграции и написания кода («второй пилот»).

## 1. Основы SQL и проектирование Базы Данных

**SQL (Structured Query Language)** — это язык общения с базой данных. Он позволяет создавать, читать, обновлять и удалять данные (принцип CRUD).

### 1.1. Создание структуры (Schema)
Мы создаем учебную базу данных для школы/курсов. Основные сущности:

*   **Students (Студенты):** Люди, которые учатся.
*   **Teachers (Преподаватели):** Люди, которые учат.
*   **Courses (Курсы):** Предметы (например, Матан, Программирование).
*   **Groups (Группы):** Потоки студентов с датами начала и конца.
*   **Enrollments (Зачисления):** Связующая таблица (кто в какой группе учится).

#### Пример SQL-запроса для создания таблицы студентов:
```sql
CREATE TABLE IF NOT EXISTS students (
    id INTEGER PRIMARY KEY AUTOINCREMENT, -- Уникальный номер, сам растет (+1)
    first_name TEXT NOT NULL,             -- Имя, обязательно к заполнению
    last_name TEXT NOT NULL,              -- Фамилия, обязательно
    email TEXT UNIQUE NOT NULL,           -- Почта, не должна повторяться
    phone TEXT,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP -- Метка времени создания
);
```

### 1.2. Ключевые понятия
*   **Primary Key (Первичный ключ):** Уникальный идентификатор записи (ID). Не может повторяться.
*   **Foreign Key (Внешний ключ):** Ссылка на ID из другой таблицы. Обеспечивает *целостность данных*.
    *   *Пример:* Группа ссылается на `course_id`. Нельзя создать группу по несуществующему курсу.
*   **Связи:**
    *   *One-to-Many (Один ко многим):* Один курс — много групп.
    *   *Many-to-Many (Многие ко многим):* Один студент может учиться в разных группах, в одной группе много студентов. Реализуется через промежуточную таблицу (`enrollments`).

## 2. Проблема реального мира: Импорт данных (Migration)

В теории всё красиво, но на практике мы получаем данные в формате **CSV** (Comma Separated Values) или Excel, заполненные людьми вручную.

### 2.1. Проблемы «грязных» данных (CSV)
*   **Опечатки:** «Talin» вместо «Tallinn».
*   **Формат дат:** Где-то «2025-01-01», где-то «01.01.25», а где-то просто «январь».
*   **Объединенные ячейки:** Смерть для автоматического парсинга.
*   **Человеческий фактор:** Комментарии в полях для цифр (например, в поле ID написано «мама Тани»).

### 2.2. Решение: AI-Агент для миграции
Вместо того чтобы вручную перебивать 10 000 строк, мы пишем скрипт (обычно на Python), который:
1.  Читает «грязный» файл.
2.  Пытается понять структуру.
3.  Чистит данные (нормализует даты, исправляет города).
4.  Раскладывает данные по нужным таблицам в SQL (разносит студентов в `students`, группы в `groups`, связи в `enrollments`).

> **Философия автоматизации:** Мы не пытаемся сделать 100% автомат сразу. Сначала мы делаем **MVP** (Minimum Viable Product). Пусть скрипт обработает 90% данных, а 10% ошибок выдаст в лог — это лучше, чем делать всё руками.

## 3. Концепция AI-Агентов

**Агент** — это программа (скрипт), которая выполняет сложную последовательность действий, используя инструменты (БД, API, поиск в интернете) для достижения цели.

### Пример архитектуры агента для новостного портала (обсуждалось на лекции):
1.  **Сбор (Input):** Агент идет в Twitter/Facebook/RSS, собирает новости по теме.
2.  **Обработка (Processing):** Агент (через LLM) читает текст, делает саммари (краткое содержание), переводит на нужный язык.
3.  **Обогащение:** Агент ищет подходящую картинку (через API фотостоков или генерацию).
4.  **Публикация (Output):** Агент сохраняет готовую статью в базу данных и публикует на сайт.

> **Важно:** Агент — это не магия. Это набор инструкций. Если вы не можете объяснить задачу «стажеру» (алгоритм действий), вы не напишете агента. Сначала нужно понять процесс вручную («на пальцах»), потом автоматизировать.

## 4. Практические советы и инсайты

1.  **Не пытайтесь съесть слона целиком.**
    Разбивайте задачу на подзадачи.
    *   *Сложно:* «Сделать полную автоматизацию школы».
    *   *Реально:* «Сделать таблицу студентов» -> «Загрузить CSV» -> «Связать с группами».

2.  **Ручное управление vs Автоматизация.**
    На старте (MVP) нормально запускать скрипты вручную и править ошибки глазами. Полная автоматизация («нажал кнопку — и улетел в космос») стоит дорого (время/деньги) и нужна только на больших объемах.

3.  **Почему не Excel?**
    Excel хорош для визуализации и простых расчетов. Но когда данных становится много (10k+ строк) и нужны сложные связи (история переходов студентов между группами, финансовый учет), Excel ломается. База данных держит структуру и не позволяет в поле «Цена» написать «Договорная».

4.  **Терпение.**
    Программирование и работа с данными — это постоянная борьба с ошибками (`bug fixing`). То, что код падает с ошибкой — это нормальная часть процесса разработки, а не неудача.

### Словарь терминов с лекции:
*   **CSV:** Текстовый файл, где данные разделены запятыми.
*   **CRUD:** Create, Read, Update, Delete (основные операции с данными).
*   **MVP:** Минимально жизнеспособный продукт (сделай просто, но чтобы работало).
*   **API:** Способ, которым одна программа общается с другой (например, сайт с базой данных).
*   **Frontend:** То, что видит пользователь (кнопочки, таблицы на сайте).
*   **Backend:** То, что работает «под капотом» (база данных, скрипты, агенты).
